# Alem Challenge Hub

Платформа для кейса HackAlem / AI SANA «Рейтинг качества бизнес-задач и открытый выбор команд». Разработана командой Power of Oil&Gas. Бизнес превращает описание в подтверждённую карточку; команды самостоятельно откликаются; бизнес выбирает исполнителей и принимает результаты этапов.

## Быстрый запуск на Windows

Нужны Python 3.11+ и Node.js 22.12+ (или 24 LTS), npm. При первом запуске нужен интернет для установки зависимостей. Внешние шрифты и другие CDN для интерфейса не используются.

```bat
start_project.bat
```

Откройте http://localhost:5173. API: http://localhost:8000/docs.

Если уже запущена другая копия проекта, используйте отдельные порты:

```bat
start_project.bat 8001 5174
```

Тогда приложение доступно на http://localhost:5174, API на http://localhost:8001/docs. Первый аргумент — порт backend, второй — frontend. Скрипты выставляют соответствующие API URL и CORS origin. `--strictPort` не позволяет незаметно переключить frontend на неподходящий порт.

### Ручной запуск

```bat
cd backend
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
copy .env.example .env
.venv\Scripts\python -m uvicorn app.main:app --reload --port 8000
```

В другом терминале:

```bat
cd frontend
npm ci
npm run dev
```

Если `.env` уже существует, сохраните его. Не перезаписывайте свои настройки. Для macOS/Linux используйте `.venv/bin/python` и `cp` вместо `copy`.

## Сквозной сценарий

1. Зарегистрируйтесь как бизнес. В личном кабинете видны только ваши задачи. Введите описание или выберите один из пяти явно обозначенных учебных примеров.
2. Помощник выделит известные сведения и задаст минимум три вопроса. Вопросы идут по одному и привязаны к полям; видны подсказки, назначение вопроса и потенциальные баллы.
3. Ответьте хотя бы на три вопроса. Можно ответить «Не знаю»: это не подменяется выдуманными фактами и не приносит баллов.
4. Ответы переносятся дословно в соответствующие поля. Проверьте и отредактируйте карточку. Предварительная оценка пересчитывается сервером во время ввода.
5. Нажмите «Оценить с ИИ»: модель проверит конкретность по критериям и вернёт цитаты. Изучите частичные баллы и рекомендации, подтвердите факты, затем отдельно опубликуйте задачу.
6. В каталоге задачи отсортированы по убыванию рейтинга. Поиск, фильтры по отрасли и готовности доступны исполнителям. Низкий рейтинг не скрывает опубликованную задачу.
7. Пользователь с ролью исполнителя отправляет идею, план, срок и HTTP(S)-ссылку. Количество откликов не ограничено.
8. Бизнес сравнивает отклики и выбирает одну, несколько или ни одной команды.
9. Для выбранной команды бизнес подтверждает фактический результат этапа. Исследование — 0–20 баллов, прототип — 0–30, проверка результата — 0–50. Бизнес вводит целую оценку вручную; максимум не выставляется автоматически. Это отдельные баллы прогресса по отклику, они не меняют рейтинг бизнес-задачи. Каждый этап учитывается один раз.
10. Через «Дополнить задачу» можно изменить опубликованную карточку. После новой оценки и ручного подтверждения рейтинг обновляется, задача остаётся в каталоге.

## Архитектура

- `frontend/src/pages` — React: главная, каталог, описание, пошаговые уточнения, редактор, карточка и предложения.
- `frontend/src/api/client.js` — клиент API с ограничением ожидания и понятными ошибками.
- `backend/app/routers/challenges.py` — анализ, предварительный рейтинг, сборка, подтверждение, публикация и каталог.
- `backend/app/routers/proposals.py` — профили команд, открытые отклики, решения бизнеса, подтверждение этапов.
- `backend/app/services/ai_service.py` — структурированный AI-анализ, проверка цитат, локальный помощник и перенос ответов.
- `backend/app/services/rating_service.py` — единственный источник формулы рейтинга для frontend и backend.
- `backend/app/schemas.py` — валидация входов, ограничение длины, обязательное подтверждение, безопасные ссылки.
- `backend/app/database.py` — SQLite, внешние ключи, транзакции, уникальность этапов; совместимое добавление новых таблиц и `ai_mode` к существующей БД.
- `backend/app/services/seed_service.py` — 5 синтетических карточек, 5 команд, 5 предложений при пустой БД. Пять исходных описаний разной полноты также доступны в форме создания.
- `backend/tests/test_workflow.py` — автоматические проверки на отдельной временной БД; реальные данные не затрагиваются.

Черновик формы сохраняется в `sessionStorage` текущей вкладки. После сборки ответы и карточка хранятся в SQLite. При смене серверной версии устаревший локальный черновик не применяется. Это MVP без синхронизации правок между пользователями.

## Рейтинг

| Поле | Баллы |
|---|---:|
| Контекст | 10 |
| Потребность | 10 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт | 5 |
| Формат взаимодействия | 5 |
| Всего | 100 |

Группировка соответствует ТЗ: контекст + потребность = 20; связь с бизнесом = 10. Название обязательно для подтверждения, но не приносит баллов. Каждое поле разделено на 2–3 содержательных критерия. Баллы частичные: например, в данных отдельно оцениваются источник (6), формат (4), объём/период (5), доступ (5). Сам факт заполнения не даёт весь вес. Пробелы и служебные ответы «Не знаю», «Не указано», `TBD`, `N/A` и аналогичные обозначения неизвестности не учитываются. Официальный рейтинг до ручного подтверждения равен нулю; предварительная полнота явно отделена от него.

Уровни: 0–39 — черновик; 40–69 — рабочая; 70–89 — готовая; 90–100 — приоритетная. «Черновик» как уровень рейтинга не равен неопубликованному черновику записи. Опубликованная задача с 10 баллами открыта для откликов.

Рейтинг измеряет конкретность и полноту постановки задачи по рубрике. ИИ возвращает дословные доказательства выполнения критериев, а сервер проверяет цитаты и суммирует фиксированные веса. Он не доказывает достоверность бизнеса, наличие реальных данных или качество результата: содержательную проверку выполняет человек. Подсказки просят указывать измеримые критерии и условия доступа.

## ИИ

В `backend/.env`:

```env
OPENAI_API_KEY=your_api_key
OPENAI_MODEL=gpt-5-mini
USE_AI=true
```

Ключ используется только сервером. Не помещайте его в Vite/React. `.env` исключён из Git. Без ключа приложение работает в явно обозначенном локальном режиме.

ИИ работает в двух местах: смысловая оценка карточки по кнопке «Оценить с ИИ» и анализ свободного описания, извлечение сведений и предложение вопросов по полям. Используется строгий JSON Schema; каждый извлечённый факт дополнительно проверяется как дословная цитата исходного текста. Неподтверждённые цитаты отбрасываются. Это консервативная защита от новых фактов: семантическую правильность отнесения цитаты к полю всё равно проверяет бизнес.

Ответы пользователя уже связаны с полями и переносятся детерминированно, без повторного запроса к модели. Локальный режим распознаёт явные метки полей, сохраняет исходную потребность и формирует вопросы по пробелам. В обоих режимах минимум три вопроса; если основные сведения уже есть, предлагаются вопросы на проверку. Публикация и выбор команды всегда ручные.

Запрос ограничен 55 секундами, автоматические повторы отключены. При отказе, неполном/некорректном ответе и исключении используется локальный режим; в журнал не выводятся ключи, исходные описания или тексты ответов. См. [контракт ИИ](docs/AI_CONTRACT.md) и [официальную документацию Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

## Границы MVP

Есть регистрация, две роли, серверная проверка владельца, PBKDF2-хеши паролей и HttpOnly-сессии. Для публичной эксплуатации дополнительно нужны HTTPS, восстановление доступа, подтверждение email и защита входа от перебора. Учебные данные и ссылки в seed не являются реальными проектами. Локальный помощник не является LLM. Реальный OpenAI-запрос проверен: неполная учебная карточка получила 45/100, mode=openai. Баллы прогресса учитываются в рамках конкретного отклика, без общего рейтинга команд. Полный проектный трекер и обучение модели в объём хакатона не входят.


## Аккаунты и прежние данные

Новые пользователи выбирают роль при регистрации. Бизнес видит только свои черновики и публикации, управляет собственными откликами и этапами. Исполнитель видит опубликованный каталог, отправляет отклик от собственного имени и видит свои отклики. Подмена ID или роли на клиенте не даёт дополнительных прав.

Существующие задачи сохранены в отдельном аккаунте `owner@alem.local`. При первом переносе случайный пароль записывается в приватный файл `backend/data/initial-access.txt` (исключён из Git). Старые отклики аналогично принадлежат `team@alem.local`. Новая регистрация не получает чужие старые данные. Перед миграцией сохранена резервная копия SQLite.

Оценка привязана к точному тексту карточки и версии рубрики. Повторный запрос для неизменённого текста возвращает сохранённую ИИ-оценку. Любая правка требует новой оценки перед подтверждением. Без доступа к ИИ явно показывается локальная предварительная оценка; она не выдаётся за ответ модели. Старые рейтинги пересчитаны локально и помечены соответствующим образом.

API: запросы изменения требуют заголовок `X-Requested-With: Alem` и сессионную cookie; браузерный Origin должен совпадать с настроенным FRONTEND_ORIGIN. React-клиент отправляет их автоматически.


## Языки, темы и оценки этапов

В верхней панели доступны ҚАЗ / РУС / ENG и кнопка светлой/тёмной темы. Настройки сохраняются в localStorage, применяются после обновления страницы и синхронизируются между вкладками. При первом запуске тема следует настройке системы. Переключение языка не сбрасывает введённые ответы, оценки и формы. Пользовательские описания, доказательства, имена и цитаты остаются в исходном виде.

Статические переводы находятся в shared/translations.json; frontend и backend используют общий словарь. Клиент передаёт Accept-Language. Новые ИИ-вопросы и пояснения оценки содержат варианты на русском, казахском и английском. Старые вопросы без переводов при смене языка показывают локализованный вопрос по соответствующему полю. Старые пояснения без перевода заменяются пояснением о сохранённой оценке; критерии доступны на выбранном языке. Внешний перевод данных пользователя при переключении языка не вызывается.

После выбора исполнителя бизнес вводит баллы за конкретный этап: исследование 0–20, прототип 0–30, проверка результата 0–50. Поле изначально пустое. Обязательны обоснование и подтверждение. API требует целое поле points, проверяет диапазон для выбранного этапа и не позволяет повторно начислить баллы. Ноль — допустимая выставленная оценка. В истории отображается фактическая оценка и максимум, например 12/20. Старые выставленные оценки сохраняются; общий прогресс — сумма оценок этапов, отдельно от рейтинга качества задачи.

Проверки обновления: 17 backend-тестов, production-сборка, проверка полноты словаря и параметров переводов, реальные запросы ИИ на казахском и английском. В браузере проверены три языка, темы, сохранение настроек после обновления, сохранение формы при смене языка и выставление 12/20.


## Репутация исполнителей и претенденты

В списке предложений бизнес видит средний рейтинг исполнителя из 100 и число завершённых заданий. Завершённым считается выбранный отклик с оценками всех трёх этапов. Среднее вычисляется по суммам баллов завершённых заданий; текущая задача и незавершённые задания исключаются. Нулевая завершённая оценка учитывается, отсутствие истории отображается как «Пока нет оценок». При нескольких завершённых откликах исполнителя на одну задачу учитывается последний; прежние командные профили разделяются по team_id.

В правой верхней части карточки задачи отображается число уникальных претендентов, подавших отклик, включая уже рассмотренные отклики. Повторные отклики одного аккаунта не увеличивают число. У бизнеса счётчик ведёт к предложениям по этой задаче. Каталог и список предложений обновляются при возвращении фокуса во вкладку. Индивидуальные данные чужих откликов исполнителям не раскрываются.

Favicon: frontend/public/favicon.svg, подключён в frontend/index.html. Новые подписи доступны на русском, казахском и английском, оформление совместимо с обеими темами.
